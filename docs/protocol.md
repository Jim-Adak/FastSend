# FastSend V-1 协议

TCP 默认端口 45455。控制消息为 UTF-8 JSON，以换行结束，单条不超过 16 KiB。文件内容按声明大小读取，不能按 TCP 数据包边界划分消息。大小以十进制字符串传递，支持空文件，上限 1 TiB，并在接收时检查磁盘可用空间。

1. 发送 offer：type=offer、protocol=FastSend、version=1、name、size、device。
2. 接收端验证文件名、版本、大小，等待本地用户确认，此时不能发送文件体。
3. 接收端发送 accept、reject 或 error。等待或无进展 60 秒后超时。
4. accept 后发送方传送恰好 size 字节的文件体。
5. 文件体后发送 finish JSON，携带内容的 sha256。
6. 接收端检查哈希，将临时文件以不覆盖方式改名，再发送 complete JSON 和相同哈希。
7. 发送端收到 complete 才显示成功。文件已保存但确认消息丢失时，发送端可能显示失败；重新发送会创建编号副本。

发送状态：连接 → 等待同意 → 发送 → 等待校验 → 成功/失败。
接收状态：解析 → 等待同意 → 接收 → 校验 → 保存 → 成功/失败。

使用 Qt 事件驱动方式，发送队列约 256 KiB，单次读取不超过 64 KiB；接收循环约每 1 MiB 让出事件循环。每个节点一个活动任务，忙碌时拒绝其他连接。

QTemporaryFile 在接收目录独占创建临时文件，失败时清理。最终使用 QFile 不覆盖改名，同名时尝试 filename (1).ext。文件名拒绝路径分隔符、控制字符、Windows 保留设备名和尾部空格/句点。

UDP 发现端口 45454，每 3 秒向 IPv4 网卡广播 app、version、id、name、TCP port；接收时使用数据报源 IP，忽略自身 ID，12 秒未出现则移除，最多缓存 128 个设备。公告不包含文件路径，也不是身份认证。
